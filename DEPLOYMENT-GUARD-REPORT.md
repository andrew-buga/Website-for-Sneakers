## Technical Architecture

### Level 1: Pre-Commit Hooks
**File**: `.husky/pre-commit`

**Execution Flow**:
```
git commit -m "changes"
    ↓
Hook triggers automatically
    ↓
1. TypeScript check (npx tsc --noEmit)
   └─ If errors: Exit 1, commit blocked
    ↓
2. ESLint on staged files (npx lint-staged)
   └─ ESLint auto-fixes issues
   └─ If errors remain: Exit 1, commit blocked
    ↓
3. Merge conflict check (git diff --check)
   └─ If conflicts: Exit 1, commit blocked
    ↓
All pass → Commit created ✅
```

**Performance**: 2-3 seconds typical

---

### Level 2: Post-Merge Hooks
**File**: `.husky/post-merge`

**Execution Flow**:
```
git pull / git merge / git rebase
    ↓
Hook triggers after merge completes
    ↓
1. Check if package.json changed
   └─ If yes: run npm install
    ↓
2. Check if pnpm-lock.yaml changed
   └─ If yes: run pnpm install
    ↓
3. TypeScript verification (optional warning)
    ↓
Completes (no blocking, recovery-only)
```

**Performance**: 5-10 seconds (depends on npm install)

---

### Level 3: GitHub Actions CI/CD
**File**: `.github/workflows/deploy-check.yml`

**Execution Flow**:
```
git push origin main/develop
    ↓
GitHub detects push
    ↓
Workflow starts (Ubuntu runner)
    ↓
1. Checkout code
2. Setup Node.js 22 (with npm cache)
3. Install dependencies (npm install)
4. TypeScript check (npx tsc --noEmit)
5. ESLint validation (npm run lint - full codebase)
6. Environment validation (npm run check:env)
7. Build verification (npm run build)
8. Page count check (120/120)
9. Status reporting (success/failure)
    ↓
All pass → Green checkmark ✅
Any fail → Red X, detailed failure message ❌
    ↓
Vercel sees status → Deploy (if passing)
```

**Performance**: 15-20 minutes typical

**Concurrency**: Runs on `ubuntu-latest` with 30-minute timeout

## ⚠️ MANUAL SETUP REQUIRED IN GITHUB

The code is complete and deployed, but GitHub requires manual configuration to activate the full system.

### Required: Create GitHub Secrets

**Steps**:
1. Go to: **Repository → Settings → Secrets and variables → Actions**
2. Create 3 new secrets:

```
Name: NEXT_PUBLIC_API_BASE_URL
Value: https://api.example.com  (or your actual API URL)

Name: DATABASE_URL
Value: postgresql://user:password@host/db  (or your actual DB URL)

Name: NEXTAUTH_SECRET
Value: <your-random-secret-key>  (use: openssl rand -base64 32)
```

### Optional: Enable Branch Protection

**For extra safety** (protects main from accidents):

1. Go to: **Repository → Settings → Branches**
2. Click "Add rule"
3. **Branch name pattern**: `main`
4. Check:
   - ✅ Require pull request reviews before merging
   - ✅ Require status checks to pass before merging
   - ✅ Require branches to be up to date
5. Select check: **"Deployment Guard - Pre-Deploy Checks"**
6. Save

**Effect**: No code can merge to main if GitHub Actions fail

## Support & Troubleshooting

### Common Issues

**Issue**: "Pre-commit hook failed"
- **Cause**: TypeScript error, ESLint error, or merge conflict
- **Fix**: Read error message, fix code, retry commit

**Issue**: "GitHub Actions workflow not running"
- **Cause**: Secrets not set or workflow syntax error
- **Fix**: Set GitHub Secrets, verify workflow file syntax

**Issue**: "Dependencies out of sync"
- **Cause**: package.json changed, post-merge didn't run
- **Fix**: Run `npm install` manually, try pull again

**Issue**: "Build generates < 120 pages"
- **Cause**: Route error in one of the 40 routes
- **Fix**: Check GitHub Actions logs, reproduce locally with `npm run build`
